# Level Solver (слепой решатель)

Проверяет честность уровня (столп 4 approach.md): у каждого слова ровно один
дом, и независимый решатель, видя только слова и названия категорий,
раскладывает их так же, как задумал генератор. Расхождение = брак уровня.
Ловушка валидна, если решатель всё равно кладёт слово в home.

Три части: детерминированная подготовка (скрипт), независимый AI-прогон
(субагент без доступа к ответам), детерминированная сверка (скрипт).

## Процедура

0. **Свежесть старых вердиктов.** Прогон валиден, только если
   `<имя>.solution.json` НОВЕЕ файла уровня (сверь mtime). Уровень правился
   после прогона = вердикт устарел, прогоняй заново (урок 31.07: в volume1
   8 из 10 «PASS» были от старых редакций уровней, свежий прогон нашёл FAIL).
1. **Ослепление.** `python3 tool/scripts/solver_blind.py <файлы уровней>` -
   создаёт `levels/solver/<имя>.blind.json`: названия категорий по алфавиту +
   плоский перемешанный список слов. Ответы, ловушки и id туда не попадают.

2. **Независимый прогон.** Для каждого уровня запусти ОТДЕЛЬНОГО субагента
   (Agent, general-purpose; несколько уровней - параллельно). В промпт вставь
   содержимое blind-файла ЦЕЛИКОМ и шаблон ниже. Жёсткие правила честности:
   - субагент получает только blind-данные в тексте промпта;
   - ему запрещено читать файлы проекта и что-либо искать: только рассуждение
     над списком слов;
   - решает сам: никаких подсказок от тебя про темы, ловушки или историю пакета.

   Шаблон промпта субагенту:

   > Ты играешь в словесный пазл. Даны названия категорий и перемешанный
   > список слов; в каждой категории ровно 4 слова, каждое слово принадлежит
   > ровно одной категории. Не читай никакие файлы и не используй поиск -
   > только рассуждение. Разложи ВСЕ слова по категориям. Если слово
   > правдоподобно смотрится в двух категориях, положи его туда, где оно
   > уместнее, и зафиксируй сомнение. Верни ТОЛЬКО JSON:
   > { "groups": [ { "category": "<имя из списка>", "words": ["w1","w2","w3","w4"],
   >     "confidence": 1-5 } ],
   >   "hesitations": [ { "word": "...", "also_fits": "<категория>", "why": "коротко" } ] }
   >
   > Данные уровня: <содержимое blind.json>

   Ответ субагента сохрани как `levels/solver/<имя>.solution.json`
   (только JSON, без обёрток).

3. **Сверка.** `python3 tool/scripts/solver_check.py <уровень.json> <решение.json>`.
   Пишет `levels/solver/<имя>.report.md` и возвращает:
   - `0` PASS - решатель разложил 1в1;
   - `1` FAIL - есть расхождения: уровень бракуется;
   - `2` структурная ошибка решения (не 4 слова, потерянное слово):
     это сбой формата, а не уровня - переспроси субагента один раз,
     приложив список ошибок из вывода скрипта.

4. **Итог пользователю.** Таблица по уровням: точность, вердикт, судьба
   каждой ловушки (валидна? отметил ли решатель сомнение?), сомнения.
   Пакет считается прошедшим, только если PASS у всех уровней.

## Что делать с FAIL

FAIL чинит генератор, не решатель: слово с расхождением либо заменить
в уровне (скилл `level-generator`, слова только из базы), либо признать
ловушку невалидной и переделать (см. SCHEMA.md: ловушка обязана быть
БЕССПОРНЫМ членом home). После правки - повторный полный прогон
(ослепление заново: seed зависит от состава слов).

## Чего не делать

- Не решай уровень сам в основном контексте: ты видел ответы, твой прогон
  не слепой. Решает только субагент с blind-данными.
- Не правь solution.json под ответы и не перезапускай решателя "до победы":
  один прогон = один вердикт (повтор только после починки уровня или
  структурной ошибки формата).
- Не подменяй этим скиллом численную оценку сложности (шаг 5):
  hesitations и confidence из отчёта - сырьё для неё, не итог.

## Динамика - отдельная проверка

Слепой прогон отвечает на вопрос «однозначен ли уровень семантически».
Модификаторы (половинки/лёд/«?»/цепь) раскладку слов не меняют и в
ослепление не попадают. Проходимость ДИНАМИКИ (выкладка, ритм досыпки,
лимит ходов, модификаторы) проверяется симулятором:
`python3 tool/level-tool/scripts/sim_playability.py <pack.handoff.json>`
(или `--all` по всем пакам playable). В генераторе тот же симулятор
стоит hard-гейтом (`web/src/core/simulatePlayability.ts`): уровень с
жёстким тупиком, нехваткой лимита или сломанным ритмом бракуется до
сдачи. Полный вердикт по уровню = слепой решатель PASS + симулятор PASS.
