# Level Evaluator (сложность и фан)

Выставляет уровню две оценки по модели `levels/EVAL.md` (источник правды,
итеративно улучшается): D (сложность) и F (фан), каждая с объяснением
по факторам. Задание требует «числовая оценка + из чего складывается»,
поэтому разбивка обязательна, голое число не сдаётся.

## Предусловия

Оценка выставляется только уровню, прошедшему слепой решатель (скилл
`level-solver`): его сомнения и уверенность - вход обеих шкал.
Нет свежего `levels/solver/<имя>.solution.json` (или уровень менялся
после прогона) - сначала решатель. Solver FAIL = уровень бракован:
F не выше 3, D не выставляется, отправляй чинить в `level-generator`.

## Процедура

1. Прочитай `levels/EVAL.md` ЦЕЛИКОМ - формулы и якоря бери оттуда,
   не по памяти (файл живой, мог измениться после этого скилла).
2. Запусти `python3 tool/scripts/eval_metrics.py <файлы уровней>` -
   детерминированная часть: M, валидные ловушки и ага-моменты,
   незапланированные сомнения, редкие слова (zipf), K, повторы,
   кандидаты смежности из базы, уверенность решателя.
3. Семантические суждения дай сам по якорям EVAL.md:
   - узнаваемость каждой категории (конкретная бытовая или абстрактная);
   - сферы жизни и разнообразие; тематический сюжет;
   - смежные пары: из кандидатов базы оставь только пары с реальной
     путаницей у решателя или заявленным разрезанием темы.
4. Собери D и F по формулам, каждый фактор - с числом и одной строкой
   объяснения. Запиши:
   - `levels/eval/<имя>.eval.json`: `{"difficulty": {"score", "factors"},
     "fun": {"score", "factors"}, "solver_verdict", "notes"}`;
   - `levels/eval/<имя>.eval.md`: те же факторы словами.
5. Сверь с калибровкой EVAL.md: эталоны обязаны попадать в цель с
   допуском +-1. Не попадают - СТОП: это сигнал чинить модель, покажи
   пользователю расхождение и предложи правку EVAL.md (файл итеративный),
   после правки - повторный прогон всех эталонов и новая строка таблицы.
6. Сводка пользователю: таблица уровней (D, F, топ-факторы), отдельно
   красные флаги (незапланированные сомнения, редкие слова, «пресные»
   уровни без ага-моментов).

## Чего не делать

- Не оценивай уровень, который не прошёл слепой решатель, и не подменяй
  его эмпирику своим прочтением уровня: ты видишь ответы, решатель нет.
- Не подгоняй факторы под «красивое» число: если модель даёт странный
  результат, правь EVAL.md через пользователя, а не отчёт.
- Не меняй EVAL.md втихую: каждое изменение модели = отдельный коммит
  + повторная калибровка на эталонах.
