# Промпт: intent_parser

**Версия:** `intent-parser-v1`
**Проход:** свободное пожелание заказчика → структурированный конфиг блока
**Право менять что-либо в базе:** нет

---

## Зачем

Заказчик пишет словами: «блок про еду и путешествия, без спорта, побольше
ловушек на цветах». Инструмент обязан показать, **как он понял эти слова**,
и дать поправить интерпретацию до генерации. Иначе непонятно, что именно
поехало в фильтр, и результат нельзя обсуждать.

## Промпт

```
Ты превращаешь пожелание продюсера в конфиг генератора уровней.

Доступные поля конфига и их смысл:

  includeThemes           только эти тематические сферы (список из словаря ниже)
  excludeThemes           эти сферы исключить
  trapThemes              на этих темах просят ловушки
  spikePositions          позиции пиков сложности внутри блока, 1..10
  recoveryPositions       позиции передышек
  categoryCorridor        [мин, макс] категорий на уровень
  rarityRange             [мин, макс] редких слов на уровень
  maxMetaDepth            максимальная глубина вложенности категорий
  allowedModifiers        ["chains"] либо []

Доступные тематические сферы: <58 тем из снимка базы>

Правила:
1. Ничего не выдумывай. Если сфера не из списка — не подставляй похожую.
2. Каждое решение сопровождай фрагментом исходного текста, который его вызвал.
3. Фразы, которые не понял, вернуй отдельным списком unrecognized —
   молча угадать хуже, чем честно сказать «не понял».
4. Не заполняй поля, о которых в тексте ничего нет.

Ответ строго JSON:

{
  "patch": { ...только заполненные поля... },
  "matches": [ {"field": "...", "value": "...", "source": "фрагмент текста"} ],
  "unrecognized": ["фрагмент", "..."]
}
```

## Где это работает в сдаваемой версии

В публичной статической версии этот проход выполняется **детерминированным
разбором** по словарю тем (`web/src/core/intentParser.ts`), а не живым вызовом
модели. Причины названы в `docs/DECISION_LOG.md` §8: проверяющий обязан увидеть
работающий инструмент при любом состоянии ключа, а результат интерпретации
всё равно должен быть детерминированным фильтром — иначе один и тот же текст
давал бы разные блоки.

Формат ответа у обоих вариантов одинаковый, поэтому замена реализации
не требует изменений в интерфейсе.
