## 1. Что случилось

Игра — пазл «разложи пузыри со словами по категориям». Генератор собирает
уровни из базы: категория + четвёрка слов. Сгенерированная двадцатка уровней
оказалась неиграбельно трудной, и разбор упёрся в один пузырь.

На втором уровне стояла группа **BOARD GAMES: `Life`, `risk`, `sorry`,
`trouble`**.

Факт верный: Trouble — настоящая настольная игра Hasbro 1965 года, как и Life,
Risk, Sorry!. Формально с группой всё в порядке. Играть невозможно: игрок видит
четыре обычных английских слова и не понимает, что их объединяет, пока не
разложит всё остальное методом исключения.

Проверка по живым ассоциациям людей (датасет SWOW-EN, 1.23 млн ответов
«назовите первое, что приходит в голову»):

```
trouble ->  bad 0.08 · problem 0.07 · double 0.07 · difficulty 0.03 · danger 0.03
trouble <-  mischief 0.13 · predicament 0.10 · bother 0.08 · turmoil 0.08 · hassle 0.06
```

Ни одной настольной игры, ни в одну сторону. Тяга `trouble` к пулу
`monopoly / scrabble / chess / checkers` = **0.000**.

Для контраста слово, которое работает:

```
orange  ->  fruit 0.21 · color 0.09 · apple 0.08 · citrus 0.06 · juice 0.05
orange  <-  tangerine 0.38 · mandarin 0.33 · juice 0.28 · carrots 0.28 · carrot 0.24
```

Оба значения живут в голове у людей. Поэтому `orange` — лучшая ловушка
оригинала: фрукт рядом с овощами, ошибиться можно честно, а поняв — обрадоваться.

## 2. Почему база это пропустила

Вот вся запись связи `trouble → BOARD GAMES`:

```
source            seed_manual
reason            "Trouble is a game played on a board"
fit_score         0.97
obviousness_score 0.85
semantic_status   unreviewed
sense_id          NULL
```

`sense_id = NULL` означает: **не указано, в каком значении слово входит в
категорию**. База считает, что у `trouble` смысл ровно один — настольная игра.
Отсюда посчитанная неоднозначность 0.079 («слово чистое») и пройденные пороги
качества.

Замер по всей базе:

| | |
|---|---|
| связей всего | 18 882 |
| из одного захода `seed_manual` | **17 556 (93%)** |
| с шаблонным обоснованием вида «X is a …» | 9 089 |
| `fit_score = 0.97` | **92% всех связей** |
| `semantic_status = unreviewed` | 18 805 из 18 882 |
| **связей без указанного значения (`sense_id IS NULL`)** | **17 568 (93%)** |
| слов, у которых заведено хоть одно значение | **231 из 10 461** |
| слов, у которых заведено два и более | 230 |

**Корень в одну строку: база хранит написания, а не значения.**

`orange` попал в те 231 слово — у него заведены `orange_color` и `orange_fruit`,
поэтому с ним база осторожна. У `trouble`, `risk`, `sorry`, `cow`, `hand`,
`back` — ноль значений. У `Life` заведены ровно два: `life_cereal` и
`life_game`. Хлопья и настольная игра. Значения «жизнь» нет.

Заодно видно, что `fit_score` как параметр не существует: 0.97 у 92% связей.
Отличить `chess` (очевидная настольная игра) от `trouble` (игра только для того,
кто ей играл) нечем — оба 0.97 / 0.85.

## 3. Что нужно сделать

### 3.1 Завести значения словам, у которых их несколько

Сейчас 231 слово из 10 461. Задача — покрыть значениями хотя бы те слова,
которые реально многозначны и уже используются в уровнях.

Требования:

- у каждого значения свой `sense_key`, определение и часть речи;
- **у слова помечено доминирующее значение** — то, которое человек называет
  первым, если спросить без контекста. Для `trouble` это «неприятность», а не
  игра. Этого поля в схеме сейчас нет, его надо добавить;
- каждая связь `memberships` указывает конкретное значение (`sense_id`), а не
  NULL. Исключение уже есть и остаётся: категории игры слов, где важно
  написание, а не смысл (`sense_mode = 'surface_form'`);
- пропущенное значение не должно молча считаться успехом. Сейчас NULL проходит
  все проверки; должно быть наоборот.

Порядок работ: у базы уже есть механизм `sense-gaps` (очередь слов на разведение
значений) и карта ручных решений `data/seed/_sense_map.json`, применяемая на
всех путях импорта. Использовать их, а не заводить третий механизм.

### 3.2 Новый вывод: слово в этой категории стоит НЕ в главном значении

Это и есть искомый признак «подвоха». Он вычисляется, а не размечается руками:

```
слово входит в категорию значением X
доминирующее значение слова — Y
X ≠ Y  ->  связь помечается как «не в главном значении»
```

`trouble → BOARD GAMES` получает эту пометку. `chess → BOARD GAMES` не получает.
`orange → FRUITS` не получает, `orange → COLORS` тоже не получает: у `orange`
оба значения сильные, и это отдельный, законный случай — его надо отличать от
подвоха, а не сваливать в одну кучу.

Предлагаемое различение (обсуждаемо):

- **главное значение** — доминирующее;
- **живое второе значение** — не доминирующее, но известное большинству
  (`orange` как цвет). Это ценный материал: на нём строятся ловушки;
- **специальное значение** — известно только тем, кто в теме (`trouble` как
  игра, `cut` / `force` / `pass` как приёмы карточных фокусов). Для первой
  линейки уровней запрещено, для поздней кампании допустимо.

### 3.3 Порог для генератора

У генератора есть профили качества (`data/content/generation_profiles.yaml`),
и у профиля первой линейки `first_lineup` уже есть похожий по духу порог
`max_secondary_senses` — он считает связи со статусом `alternative`. Этот
статус проблему не ловит: `trouble → BOARD GAMES` имеет статус `approved`.

Нужен порог по новому признаку: **сколько слов четвёрки стоят не в главном
значении**. Для первой линейки — ноль или одно.

### 3.4 Чем проверять результат

В проекте уже есть детерминированная оценка уровня по двум шкалам —
`word-content eval-levels` (модель описана в `levels/EVAL.md`). Плюс замер
связности группы по SWOW:

| | медиана сильнейшей связи внутри четвёрки | групп без единой связи |
|---|---|---|
| двадцатка оригинала (эталон) | 0.061 | 41 из 188 (22%) |
| наша двадцатка | 0.000 | 100 из 192 (52%) |

**Целевой замер задачи: довести долю несвязных групп с 52% до 22% или ниже,
не потеряв мета-механику.**

## 4. Ограничения, которые нельзя нарушать

**Жёсткий порог по SWOW не годится как запрет.** Проверено: под порог «тяга
слова к своей группе ≥ 0.02» не проходят **57% пузырей самого оригинала**.
SWOW разрежен, участники просто не назвали большинство пар, и ноль там часто
значит «нет данных», а не «нет связи». SWOW пригоден для обнаружения сильного
сигнала, а не для доказательства его отсутствия.

Цена жёсткого порога на уровне группы измерена и неприемлема:

| порог связности четвёрки | четвёрок в пуле | правил | мета-пар |
|---|---|---|---|
| без порога | 1101 | 254 | ~22 |
| ≥ 0.01 | 537 | 180 | 3 |
| ≥ 0.02 | 425 | 159 | **1** |

Мета-механика (собранная группа оставляет пузырь для другой группы) —
существенная часть игры, и порог 0.02 её убивает. Поэтому связность по SWOW
должна работать **предпочтением при отборе**, а жёстким запретом — только на
первых уровнях.

**SWOW нельзя тянуть в генерацию напрямую.** Датасет лежит локально в
`reference/swow/` (research-only лицензия, в git не попадает). Всё, что из него
считается, должно быть посчитано отдельным шагом пайплайна и положено в базу
как готовое число. Генератор читает базу; сборка обязана оставаться
воспроизводимой на машине без датасета.

**Частотность слова задачу не решает.** Проверено на числах:

| | zipf | вердикт |
|---|---|---|
| `trouble` | **4.79** | худший пузырь пакета |
| `orange` | 4.62 | эталонный пузырь и лучшая ловушка |
| `cow` | 4.14 | идеальное слово для туториала |
| `cribbage` | 2.08 | справедливо отсеивается |
| `aglet` | 1.32 | справедливо отсеивается |

Подъём порога zipf оставит `trouble` и выбросит `cow`. zipf считает написание,
а не значение — это ровно та же слепота, что и у базы.

**Остальное не ломать.** Не переписывать генератор и модель оценки, не
останавливать текущую работу, не вводить обязательное ручное подтверждение
каждой связи: человек принимает собранный уровень целиком, а не 18 тысяч связей
по одной. Reference gate (`word-content reference-gate`) обязан продолжать
проходить. Тесты — 331, все зелёные, ронять нельзя.

```bash
cd tool/word_content_pipeline

.venv/bin/python -m pytest -q                       # 331 тест
.venv/bin/word-content sense-gaps --db database/content.sqlite
.venv/bin/word-content word-info   --db database/content.sqlite trouble
```

Ключевые файлы: схема — `src/word_content/schema.sql` и миграции
`src/word_content/migrations.py`; значения — `src/word_content/sense_map.py`,
`src/word_content/sense_gaps.py`, `data/seed/_sense_map.json`; профили —
`src/word_content/profiles.py` и `data/content/generation_profiles.yaml`;
оценка уровня — `src/word_content/level_eval.py` и `levels/EVAL.md`;
SWOW — `tool/scripts/swow_source.py`.

## 6. Что считать выполненным

1. У многозначных слов, участвующих в уровнях, заведены значения, и у слова
   помечено доминирующее.
2. Связь `memberships` знает своё значение; NULL перестал быть проходным.
3. Вычисляется признак «слово стоит не в главном значении», и он различает
   `trouble → BOARD GAMES` (подвох) и `orange → COLORS` (законное второе
   значение).
4. У профиля `first_lineup` есть порог по этому признаку.
5. Двадцатка пересобрана; доля несвязных групп по SWOW ≤ 22%; мета-связей не
   меньше, чем сейчас (22); `eval-levels` не показывает ухудшения по фану.
6. `BOARD GAMES = Life, risk, sorry, trouble` на первой линейке больше не
   собирается. Это приёмочный пример задачи.
