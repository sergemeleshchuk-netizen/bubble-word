# История промптинга

Промпты, которые двигали проект, с разбором: что в них сработало и чего
не хватило. Хронологически:

| Файл | Что это |
|---|---|
| `word-db-bootstrap.md` | Создание базы слов и pipeline с нуля (этап 1). Спецификация со схемой БД, правилами нормализации, продуктовыми правилами и списком тестов. |
| `category-depth.md` | Глубина категорий по кривой сложности: чтобы поздние уровни не собирались из тем первой десятки. |
| `word-db-audit-gpt-pro.md` | Внешний аудит той же базы через ChatGPT Pro + промпт-задание на исправления. Материалы аудита — в `word-db-audit-pack/`. |
| `base-taxonomy.md` | База как дерево категорий, а не плоский список: слой родитель-ребёнок, пул 6-8 слов как условие приёмки, рост через разрезание тем. |
| `generator-late-curve.md` | Генератор за пределами L200: плато размера 12.4, падение мета-плотности после L300, повторы слов как рычаг вместо запрета. |
| `skill-augment-base.md` | Скилл наполнения базы: три режима (разрез / углубление / тема), хабы намеренно, многозначные слова сразу со значением. |
| `word-db-production-upgrade.md` | **Не запускался, хранится под ревью.** Первый заход: база -> production content system (concept/variant/quartet, solver полного уровня, meta-цепи, кампания с cooldown). 24 раздела, 7 фаз. |
| `word-db-quality-scoring.md` | **Запущен.** Дополнение к v2: явная параметризация качества слов, названий категорий и четвёрок плюс профили генерации. Отдельная задача, основную не переписывает. |
| `word-db-production-upgrade-v2.md` | **Запущен (Phase 0-3).** Тот же замысел после возражения: ручная проверка переехала с отдельных слов и четвёрок на собранный уровень целиком. Из задания вычеркнуты `human_approved` на базовых сущностях и golden set из 500-1000 подтверждённых четвёрок. |

Пара `word-db-bootstrap` → `word-db-audit-gpt-pro` читается вместе: видно,
какие дыры в качестве данных остаются даже после подробной спецификации
и что их находит только независимая проверка чужой моделью.

Тройка `base-taxonomy` / `generator-late-curve` / `skill-augment-base` — одно
знание, разложенное по трём адресатам. Знание снято с выгрузки оригинала на
1025 уровней и записано в `reference-taxonomy.md` (замер воспроизводится
скриптом `tool/scripts/mine_bwj_org_knowledge.py`). Сама выгрузка — чужой
контент, в базу не идёт: эпизод импорта откачен, разбор в
`levels/packs/tool-test/DIFF-VS-REF.md`. Переносится способ, не словарь.
