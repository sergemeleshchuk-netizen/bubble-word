# Генератор уровней: подход

Зафиксирован 29.07.2026 после обсуждения. Дополняет `rules.md` (модель сложности,
три слоя проверки решаемости). Обновляем по мере уточнения референса.

## Принятые решения

1. **Контент: гибрид.** LLM придумывает категории и слова под заданную тему
   и целевую сложность; курированная локальная база слов и фильтры валидируют
   каждое слово. Так задание получает живой AI-воркфлоу, а качество - контроль.
2. **Слова-ловушки: да, с ростом сложности.** Ловушка: слово, правдоподобное
   для двух категорий уровня, но с однозначным домом (orange при категориях
   «фрукты» и «цвета»). С середины кривой 1-3 ловушки на уровень. Это главный
   источник «ага!»-моментов и интересной сложности жанра.
3. **Параметры поля: из референса.** Юзер наигрывает 10-15 уровней целевой игры
   (Bubble Associations: Word Game) и кладёт записи в `reference/`; с них снимаем
   число пузырей, категорий, лимиты, кривую первых уровней.

## Столпы «казуально и интересно»

1. **Категории узнаются мгновенно**: конкретные, бытовые (фрукты, кухня, спорт),
   слова частотные (zipf >= 4.3), короткие, однословные. Игрок радуется узнаванию.
2. **Интерес растёт через управляемую двусмысленность** (ловушки), а не через
   редкие слова. Редкость подключаем дозированно на поздних уровнях.
3. **Кривая сложности через близость категорий**: сначала далёкие (фрукты против
   транспорта), позже смежные (фрукты против ягод, море против рек).
4. **Честность**: у каждого слова ровно один дом; слепой решатель обязан
   разложить уровень так же, как задумал генератор, иначе уровень бракуется.

## Конвейер генерации одного уровня

1. Вход: конфиг (число категорий, слов на категорию, целевая сложность 1-10,
   опционально тема).
2. LLM предлагает набор: категории, слова, помеченные ловушки
   (`word`, `home`, `tempts`).
3. Локальные проверки без AI: блок-лист (обязателен: в сырье из WordNet
   встречаются оскорбления), частотность по wordfreq, длина, дубликаты,
   пересечения по базе (слово в пулах двух выбранных категорий = замена
   либо осознанная ловушка).
4. Слепой решатель: независимый AI-запрос получает только слова и названия
   категорий, без ответов. Расхождение = брак. Ловушка валидна, если решатель
   всё равно кладёт её в правильный дом.
5. Оценка сложности: формула из `rules.md` (очевидность связи, ловушки,
   близость категорий, размер, редкость) плюс эмпирика решателя
   (уверенность/ошибки). Выход: число + разбивка по факторам.
6. Экспорт JSON + отчёт проверки в интерфейсе инструмента.

## База слов (роль и происхождение)

Формат: категория -> пул слов, у слова метрики (zipf, длина, флаги).
Сырьё: выход пайплайна `level-generator/bubble_jam_pipeline/` (wordnet-only
уже прогнан) + ручной отбор. База нужна для валидации предложений LLM,
поиска пересечений и подсказок генератору, не как единственный источник.

## Схема уровня (по разбору референса, см. `reference-analysis.md`)

В референсе категория всегда из 4 слов, имена категорий скрыты до сборки,
лимит только по ходам, поле вмещает ~20-24 пузыря с досыпкой.

```json
{
  "level_id": 1,
  "difficulty_target": 2,
  "categories": [
    { "name": "Fruits", "words": ["apple", "mango", "peach", "plum"] }
  ],
  "traps": [ { "word": "orange", "home": "Fruits", "tempts": "Colors" } ],
  "repeats": [ { "word": "hat", "prev_level": 3, "prev_category": "Accessories" } ],
  "board": { "start_bubbles": 22, "move_limit": 39, "move_limit_k": 1.5 },
  "extensions": { "chunks": [], "chains": null, "picture_words": [] }
}
```

`move_limit = ceil(3 * категорий * K)`, K от 1.6 (просторно) до 1.25 (спайк) -
снято с уровней 2-19 референса. `repeats` - повтор слова из прошлого уровня
в новой категории (референс так играет с памятью игрока), поэтому пакет
уровней генерируется с общей историей. `extensions` - поля на будущее
(кусочки слов с L10, цепи с L20, картинки-слова), генератор v1 их не заполняет.

## Кривая для 10 сдаваемых уровней (по референсу)

- 1: туториальный, 5 далёких категорий, без лимита ходов (или K=1.8).
- 2-4: 8-10 категорий, K~1.5, первые ловушки.
- 5-7: 10-12 категорий, K~1.35, смежные категории, повторы слов из ранних
  уровней, дозированная экзотика слов.
- 8-9: 8-10 категорий, разрезание темы на две категории (время vs календарь).
- 10: спайк, hard: смежные категории + максимум ловушек, K~1.25.

Точные значения калибруем прогонами в playable-прототипе (`site/playable/`).

## Шаги (порядок работ)

AI-воркфлоу оформляем как Claude Code skills в `.claude/skills/` (решение 30.07):

- Шаг 0 (юзер, закрыт): записи референса в `reference/`; параметры поля сняты.
- Шаг 1 (закрыт): база слов `tool/data/` + **скилл `word-associations-generator`** -
  генерирует категории с пулами по теме/примеру и наполняет базу через
  `build_base.py` (валидация, блок-лист, индекс ловушек-пересечений).
- Шаг 2: схема уровня JSON + 2-3 эталонных уровня руками; прогон в playable.
- Шаг 3: **скилл `level-generator`** - на основе базы собирает уровни:
  выбор категорий под целевую сложность, ловушки из пересечений, повторы слов
  между уровнями пакета, лимит ходов по формуле; отдаёт JSON уровня.
- Шаг 4 (закрыт): **скилл `level-solver`** - слепой решатель: скрипт
  `solver_blind.py` готовит вид без ответов, независимый субагент раскладывает,
  `solver_check.py` сверяет (PASS/FAIL, вердикт по ловушкам, hesitations
  как эмпирика для шага 5). Артефакты в `levels/solver/`.
- Шаг 5 (закрыт): **скилл `level-evaluator`** - модель D (сложность) и F (фан)
  в `levels/EVAL.md` (живой файл: правка = коммит + повторная калибровка
  эталонов, допуск +-1), метрики `eval_metrics.py`, отчёты в `levels/eval/`.
- Шаг 6: веб-инструмент: UI на surge + серверный прокси для ключа AI.
- Шаг 7: 10 уровней с оценками, описание AI-воркфлоу, блоки сайта-отчёта.

Шаги 2-7 соответствуют этапам плана из блока 00 PLANNING (MD для солвера,
скиллы Solver/Generator/оценки/Export, финал).
