# Сначала воспроизвести референс, потом генерировать своё

Задача этого этапа сменила центр системы: **с онтологии слов на библиотеку
авторских игровых групп и уровней**. Пока генератор не может повторить то, что
мы точно видели на записи, его способность создавать «лучше» не подтверждена —
и массовая генерация запрещена технически, а не на словах.

## Что оказалось не так

Мы построили большую и технически аккуратную онтологию: 10 441 слово, 1 276+
принципов, 18 775 связей. Но референсная игра устроена не как энциклопедия
категорий, а как библиотека специально спроектированных четвёрок. Между «слово
есть в базе» и «уровень собирается» лежит цепочка, и она рвалась на третьем
звене:

```text
точное значение слова
→ точная связь с конкретным принципом группировки
→ конкретная авторская четвёрка      <- здесь ломалось
→ display label
→ сочетание с другими четвёрками
→ meta-зависимости и формы токенов
→ полный уровень
```

Три конкретные ошибки модели:

1. **Внутреннее правило и надпись были одной сущностью.** MUSIC на уровне 3 —
   это `pop, rock, jazz, rap`; на уровне 6 — `piano, drum, flute, guitar`. Одно
   имя, два разных правила. Пока имя было идентификатором принципа, одно
   исключало другое.
2. **Мета-механика считалась необязательной.** В референсе она начинается с
   третьего уровня и присутствует в 17 уровнях из 20; на 17-м целая категория
   собрана из результатов четырёх других.
3. **`solution_count == 1` был определением качества.** Референс намеренно
   строит интерес на пересечениях (orange — фрукт и цвет, bark — собака и
   дерево). Запрет любой двусмысленности запрещает ровно то, на чём держится
   игра.

## Что теперь есть

### Разделены три сущности

| Сущность | Где живёт | Пример |
|---|---|---|
| Внутреннее правило группировки | `categories` + `rule_type` | `music_genres`, `musical_instruments` |
| Надпись для игрока | `category_labels` | `MUSIC` |
| Допустимость надписи для правила | `group_rule_labels` | `music_genres → MUSIC` |
| Конкретная авторская четвёрка | `quartets` + `quartet_words` | `pop, rock, jazz, rap` |

`rule_type` различает девять принципов, включая те, которые нельзя свести к
таксономии: `association_hub` (CAT → meow, purr, whiskers, scratch),
`context_hub` (SLEEP → bed, blanket, pillow, dream), `meta_collector`
(MEASUREMENTS → четыре результата других категорий).

### Токен уровня перестал быть синонимом слова

`level_tokens.token_kind`: `lexical_word`, `picture_token`, `chunked_word`,
`category_output`. Форма пузыря (`token_form`) хранится отдельно от роли:
мета-токен бывает и словом, и картинкой. `observability` различает «пузырь
виден в кадре» и «категория закрылась между кадрами» — второе наблюдением не
является.

### Авторская правда отделена от семантической

`level_assignments` — дом токена в этом уровне. `level_decoys` — правдоподобные
чужие дома: `planned = 1` для спроектированных ловушек, `planned = 0` для
незапланированных. Solver теперь считает не «одно решение или брак», а отрыв:

```text
intended_partition_score   насколько естественно авторское разбиение
best_alternative_score     насколько естественна лучшая альтернатива
partition_margin           разница; ниже порога — hard reject
```

Hard reject наступает, если альтернатива не слабее авторского разбиения, если
отрыв ниже порога, если незапланированная ловушка тянет сильнее авторского
дома, если у токена нет дома или если мета-граф содержит цикл либо тупик.

### Мета стала P0

`validate-meta` симулирует прохождение уровня из стартового состояния: какие
группы можно собрать сейчас, что они выпускают, какие открываются дальше.
Ловятся циклы, тупики и токены-сироты. Все 20 уровней записи проходимы,
максимальная глубина цепочки — 2.

### Скоринг надписей перестал воевать с референсом

Ось «специфичность» больше не входит в качество: монотонный бонус за узкое имя
работал против игры, где короткий широкий ярлык — норма. Вместо неё
`label_retrospective_fit` (объясняет ли надпись четвёрку задним числом),
`label_reveal_satisfaction` (приятно ли читается в момент раскрытия),
`label_display_fitness` и описательный `label_scope`. FOOD, SCHOOL, DOCTOR,
BIRD, TREE, CAT теперь получают высокий балл, а `RELATED THINGS` — низкий.

## Числа: было и стало

Замер: `word-content reference-coverage --db … --max-level 10`.

| Проверка (уровни 1-10) | Было | Стало |
|---|---|---|
| слот → слово в базе | 375/380 | **380/380** |
| слот → однозначное значение | 379/380 | **380/380** |
| группа → правило с этой четвёркой | 83/95 | **95/95** |
| слот → связь с правилом группы | 356/380 | **380/380** |
| точная авторская четвёрка | 8/95 | **95/95** |
| прочитанная надпись совпадает | 9/24 | **24/24** |
| наша формулировка разрешается | 7/71 | **71/71** |
| мета-зависимость записана | 0/17 | **17/17** |
| форма токена записана | 0/380 | **380/380** |
| уровень воспроизводится целиком | 0/10 | **10/10** |
| diff нормализованного экспорта | — | **0** |

Столбец «было» снят уже новым замером на схеме 6 до backfill'а — то есть
сравниваются одни и те же проверки, а не разные. Прежний трёхслойный замер
(`слова 98% / концепты 80% / связи 49%`) остался в истории как более грубый:
он сопоставлял категории по имени, а для 71 группы из 95 имя — наша
формулировка, и такое сравнение измеряет совпадение базы с нашими догадками.

На всех 20 уровнях: 19 из 20 воспроизводятся полностью. Уровень 18 записан с
середины (7 групп из 11) и полным **не объявляется** — четыре не попавшие в
кадр группы и четыре их мета-ссылки честно числятся невосстановленными.

Машиночитаемые отчёты: `coverage_1_10.json`, `coverage_all.json`,
`baseline_metrics_before.json`, `baseline_metrics_after.json`.

## Как проверить или пересобрать

```bash
cd tool/word_content_pipeline

# Полная сборка с нуля, включая барьер:
bash scripts/rebuild_all.sh

# Или по шагам:
.venv/bin/word-content import-reference-backfill --db database/content.sqlite \
    --input data/reference/backfill
.venv/bin/word-content import-reference-levels  --db database/content.sqlite
.venv/bin/word-content reference-coverage --db database/content.sqlite --max-level 10
.venv/bin/word-content reference-gate     --db database/content.sqlite --max-level 10
.venv/bin/word-content validate-meta      --db database/content.sqlite
.venv/bin/word-content assess-levels      --db database/content.sqlite --origin reference_video
```

Барьер непроходимый: `generate-level-candidates` сам вызывает gate и падает,
если он не пройден. Снять его можно только явным `--skip-reference-gate` —
и это флаг отладки, результат которого контентом считать нельзя.

## Источники правды

Всё, из чего пересобирается база, лежит текстом в `data/` и коммитится:

| Файл | Что это |
|---|---|
| `data/reference/video-levels-20.json` | сама запись, обязательный regression dataset |
| `data/reference/backfill/*.jsonl` | патч: чего базе не хватает для этих уровней |
| `data/reference/backfill/resolution_decisions.csv` | как разрешилась каждая из 188 групп |
| `data/reference/group_overrides.csv` | ручные решения там, где автоматика ошибается |
| `data/reference/sense_choices.csv` | выбранное значение многозначного слова |

Патч пересчитывается командой `plan-reference-backfill`. Она детерминирована и
идемпотентна: планировщик не видит того, что сам же создал (`origin =
reference_backfill`), поэтому результат одинаков на пустой и на заполненной
базе. Правки только в SQLite запрещены — база обязана пересобираться из текста.

## Чем это не является

- **Не сдаваемым контентом.** Уровни 1-20 — чужие. Здесь они измерительный
  инструмент: единственное место, где ответ известен заранее. Правила и
  четвёрки, выведенные из записи, помечены `origin = reference_backfill` и в
  генерацию нового контента не идут ни через `build-quartets`, ни через
  `generate-level-candidates`.
- **Не доказательством качества генератора.** Совпадение с оригиналом говорит о
  полноте базы. Собрать хороший уровень и собрать чужой уровень — разные умения.
