# Первая линейка: сделано, и что осталось

Файл-передача между сессиями. Прошлая задача — «двадцать уровней лучше
оригинальных» — закрыта; ниже результат с числами и следующая задача.

---

## Что сделано

**Планка.** Модель `levels/EVAL.md` считается на пакете детерминированно:
`word-content eval-levels --prefix REF|RMK|TOP`. Две подстановки вместо
эмпирики слепого решателя названы в EVAL.md: разбиение проверяет
exact-cover-солвер, сомнение игрока — притяжение слова к соседней группе по
SWOW. Разбор: `levels/eval/reference-vs-remake.md`.

**Результат.**

| | Оригинал REF | Ремейк RMK | **Первая линейка TOP** |
|---|---|---|---|
| фан F | 7.03 | 4.47 | **8.78** |
| сложность D | 6.35 | 5.65 | **7.17** |
| честных ловушек | 29 | 8 | **105** |
| ага-моментов | 24 | 4 | **85** |
| натужных надписей | 1/188 | 33/192 | **0/192** |
| нечитаемых пузырей | 11/752 | 90/768 | **0/768** |
| знакомость слов | 0.594 | 0.538 | **0.610** |
| мета-связей | 52 | 50 | 20 |

Пакет — `levels/packs/first-lineup-20/` (`TOP001..TOP020`), разбор там же в
README. Играется на сайте: блок «06 Build Playable» → «Первая линейка».

**Что появилось в системе:**

- `decoy_pairs` + слой ловушек в генераторе: пара «дом плюс соперник вокруг
  общего слова» закладывается нарочно и объявляется в `level_decoys`;
- `labels.is_vague` — одно правило на проект: генератор им отбирает контент,
  оценщик им же штрафует готовый уровень;
- профиль `first_lineup` (однословный пузырь, потолок имён собственных, потолок
  вторых значений, запрет натужных надписей) и `cooldown_first_lineup.yaml`
  (повтор темы через 3-4 уровня, как в записи);
- `--obvious-until N` — до какого уровня брать самые очевидные правила пула;
- правило «на уровне без ловушек по записи пересечений быть не должно».

Тестов 299 -> 331.

## Задача следующей сессии: мета-связи первой линейки

Единственное место, где первая линейка проигрывает и записи, и собственному
ремейку: **20 мета-связей против 52 и 50**.

Причина измерена. Мета-пара требует, чтобы надпись правила была обычным
однословным существительным (CAT, COFFEE, DOCTOR): тогда собранная группа
оставляет пузырь с этим словом другой группе уровня. Таких надписей у нас мало,
а профиль первой линейки режет ещё:

| пул | правил | мета-пар |
|---|---|---|
| вся база | 1263 | 162 |
| first_lineup, порог средней знакомости 0.60 | 194 | 3 |
| first_lineup, порог 0.52 (текущий) | 362 | 16-21 |
| first_lineup без запрета многословного пузыря | 514 | 35 |

Дальше порогами не выжать: потолок при однословном пузыре и запрете натужных
надписей — около 21 пары. **Это задача контента, а не генератора.**

Что делать: завести короткие однословные надписи для бытовых тем, у которых
сейчас имя в два слова. CAT BREEDS -> CAT, COFFEE DRINKS -> COFFEE, EVERYDAY
DRINKS -> DRINKS. Надпись отделена от правила (`category_labels` +
`group_rule_labels`), то есть добавляется вторая надпись к существующему
правилу, а не переименовывается правило. Инструмент для наполнения есть —
скилл `word-associations-generator`; проверять прирост командой `meta-pairs`.

Ориентир: 40 пар в профиле первой линейки дают примерно 50 связей на двадцать
уровней, то есть паритет с записью.

## Что ещё названо честно и не закрыто

**Оценщик не видит групп-подвохов.** BOARD GAMES из `Life, risk, sorry,
trouble` — четыре частотных однословных токена, все измеримые признаки в
порядке, а группа при этом читается как подстава. Порог вторых значений
(`max_secondary_senses`) закрывает часть случаев, но у базы нет признака
«слово читается как типичный представитель темы». Кандидат на такой признак —
`memberships.obviousness_score`, но он сейчас почти константа: 0.85 у половины
связей.

**Регистр токенов.** В записи все 752 пузыря записаны строчными; у нас 203 с
большой буквы и 23 группы со смешанным регистром внутри (`mark, Luke, Aaron,
Ruth`). В прототипе не видно — он поднимает всё в верхний регистр, — но в
выгружаемом JSON выглядит небрежно. Решать: либо нормализовать на выгрузке,
либо чинить `display_text` в базе.

**Грани категорий** (осталось с прошлой передачи). Из одного пула строить много
правил-синонимов: farm / mammal / horned / fluffy / predators. Замер: пул FARM
ANIMALS из 20 слов даёт пять готовых групп сверх исходной; 63% слов базы
принадлежат ровно одному правилу. Ограничение тоже измерено: грани одной темы
конкурируют за одни и те же слова и работают **между** уровнями, а не внутри
одного.

## Команды

```bash
cd tool/word_content_pipeline

bash scripts/rebuild_all.sh                 # полная сборка, ~7 минут
.venv/bin/python -m pytest -q               # 331 тест

# пересобрать первую линейку ровно как сдана
.venv/bin/word-content generate-level-candidates --db database/content.sqlite \
    --limit 20 --categories 0 --seed 707 --key-prefix TOP \
    --profile first_lineup --config data/content/cooldown_first_lineup.yaml \
    --obvious-until 2

.venv/bin/word-content assess-levels --db database/content.sqlite --origin generated
.venv/bin/word-content validate-meta --db database/content.sqlite
.venv/bin/word-content eval-levels   --db database/content.sqlite --prefix TOP
.venv/bin/word-content meta-pairs    --db database/content.sqlite

.venv/bin/word-content export-level-pack --db database/content.sqlite --prefix TOP \
    --output ../../levels/packs/first-lineup-20/pack.json \
    --playable-dir ../../site/playable/levels
```

Сайт: `npx surge ./site serge-mel.surge.sh` из корня.
Мерить на копии базы, а не на рабочей: `cp database/content.sqlite /tmp/x.sqlite`.

## Что нельзя (не изменилось)

- Тянуть в генерацию контент записи: правила, четвёрки и надписи с
  `origin = 'reference_backfill'` — чужой авторский материал, здесь эталон.
- Ломать reference gate: он обязан проходить.
- Повторять слово внутри одного уровня.
- Копировать уровень записи целиком (проверка — отпечаток четвёрки).
- Подгонять модель оценки под отчёт. Если число не бьётся с ощущением от
  playable, чинится `levels/EVAL.md`, и обе двадцатки перемеряются заново.
- Говорить «готово» без прогона команд и проверки в браузере.
