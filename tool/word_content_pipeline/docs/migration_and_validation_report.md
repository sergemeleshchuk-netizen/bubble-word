# Отчёт о миграции и проверках

Работа по заданию `prompts/word-db-production-upgrade-v2.md`, фазы 0–3.

## Baseline: с чего начинали

Снимок до работы — `docs/baseline_before.json`, после — `docs/baseline_after.json`.
Обе цифры воспроизводятся командой:

```bash
word-content baseline-report --db database/content.sqlite --compare docs/baseline_before.json
```

Исходное состояние: 10 441 слово, 564 значения, 1276 категорий, 18 775 связей,
3200 четвёрок, 567 записей в слое конфликтов. Все 126 тестов зелёные,
`check-integrity` без блокеров. То есть чинилось не сломанное — чинилось то,
что называлось не своим именем и не проверялось на нужном уровне.

## Миграции

### 003 `sense_and_quartet_states`

Что сделано:

- `memberships.sense_mode`, `validation_state`, `validation_reasons`;
- `word_senses.display_text`, `is_proper_noun`;
- 510 связей игры слов получили `sense_mode = surface_form`, 98 составных со
  значением — `compound`;
- таблица `quartets` пересобрана: `review_state` → `validation_state`
  (без `human_approved`), `solver_state` → `local_check`
  (`unique` → `local_unique`).

**Инцидент и его причина.** Первый прогон миграции удалил все 12 800 слов
четвёрок. `PRAGMA foreign_keys = OFF` внутри открытой транзакции — молчаливый
no-op, а перед пересборкой шёл `UPDATE memberships`, который транзакцию открыл.
`DROP TABLE quartets` ушёл каскадом. `PRAGMA foreign_key_check` после этого
проходил: осиротевших строк не осталось, потому что их не осталось вообще.

Исправление: состав четвёрок сохраняется во временную таблицу и
восстанавливается явно, с проверкой «сколько было — столько стало». Шаг
отрабатывает одинаково независимо от состояния внешних ключей. База
восстановлена из копии, сделанной перед миграцией.

Регрессия закрыта тестами `tests/test_migrations.py`:
`test_migration_preserves_quartet_tokens` и
`test_migration_survives_open_transaction` — второй воспроизводит ровно ту
ситуацию, открывая транзакцию перед вызовом.

### 004 `content_model`

- `category_concepts`, `category_aliases`, `categories.concept_id` с backfill
  на 1276 категорий (у каждой формулировки свой принцип, пока не доказано иное);
- `structured_relations` — общий слой пар и последовательностей с ролями;
- 13 полей на `quartets`: происхождение, оценки отбора, риск-статус, версия
  валидатора, счётчики использования, последняя причина отключения;
- `quartet_words.sense_mode` и `role`;
- уровень как сущность: `level_instances`, `level_groups`, `level_tokens`,
  `level_solver_runs`, `level_decisions`, `level_decision_reasons`,
  `level_dependencies`;
- `content_runs` — провенанс любой автоматической генерации;
- представление `v_membership_eligibility` — проекция `review_status`
  на словарь задания, без второй колонки с тем же смыслом.

Обе миграции идемпотентны: повторный `migrate-content-schema` ничего не делает.
`init-db` создаёт скелет из `schema.sql` и сразу докатывает шаги, поэтому чистая
сборка и рабочая база получают одну и ту же схему.

## Правки контента

### Значения многозначных слов

Заведены значения для слов, где база хранила несколько разных смыслов под одним
словом: `bell` (предмет / Александр Белл / болгарский перец), `rose`
(цветок / имя / вино), `cricket` (насекомое / спорт), `iris` (цветок / радужка),
`jasmine` (цветок / принцесса / рис / чай / имя), `charger` (зарядка / автомобиль),
`life` (настольная игра / марка хлопьев), `spirit` (душа / авиакомпания),
`siren` (сирена / мифическое существо), `moon`.

### Категории действия

Одиннадцать связей вида «категория действия ссылается на предмет» получили
глагольные значения: `drill_bore`, `nail_fasten`, `button_fasten`, `bill_charge`,
`iron_press`, `link_connect`, `monitor_watch`, `score_goal`, `note_write`,
`rest_relax`, `pitch_throw_verb`.

Отдельный случай — категория `HAMMERED THINGS` («вещи, по которым бьют
молотком»). Она была помечена типом связи `does_action`, хотя её элементы —
объекты действия, а не исполнители. Тип связи исправлен на `used_in` в
`data/seed/tools.txt` и в трёх записях `_ambiguous.json`.

Все правки живут в текстовых источниках и переживают пересборку.

## Проверки

`check-integrity` — 18 проверок, из них 12 блокирующих. Добавлены:

| Проверка | Уровень | Что ловит |
|---|---|---|
| `sense_belongs_to_word` | блокер | значение из чужого слова у связи или четвёрки |
| `surface_mode_has_no_sense` | блокер | связь «про написание» тащит значение |
| `action_relation_pos` | блокер | связь-действие ссылается на предмет при наличии глагольного значения |
| `variant_has_concept` | блокер | формулировка без семантического принципа |
| `alias_not_a_concept` | предупреждение | слияние сделано наполовину |
| `display_collision` | предупреждение | два значения-имени с неразличимой надписью |

Переписана `conflicts_present`. Раньше она требовала непустой слой конфликтов,
и корректная база без пересечений считалась непригодной. Теперь проверяется
обратное: нет ли пересечения в четыре и более слова, для которого запрета не
записано.

`validate-levels` — 7 проверок уровней: покрытие токенов группами,
`solution_count == 1`, исход solver'а `unique`, отсутствие повторяющихся
надписей, отсутствие выключенных четвёрок, хеш у принятого уровня, наличие
отчёта о запуске solver'а.

## Воспроизводимость

```bash
bash scripts/rebuild_all.sh              # 14 шагов, ненулевой код = база не готова
word-content rebuild-all                 # то же самое через CLI
```

Команда `rebuild-all` не повторяет шаги, а запускает скрипт: две копии одного
порядка сборки неизбежно разъезжаются.

Проверено: две сборки из одних и тех же источников дают уровни с одинаковыми
хешами содержимого (`test_clean_rebuild_gives_the_same_content_hash`).
Генератор детерминирован при одинаковом seed.

## Известные ограничения

1. **Уровни не приняты.** Пять уровней выгружены в
   `data/content/level_review/` и ждут человека. Пока приёмки нет, метрики
   `accepted level count` и `quartets in accepted levels` равны нулю — это
   правильное состояние, а не пробел.
2. **Структурные категории без четвёрок.** Тринадцать парных категорий имеют
   структуру в `structured_relations`, но `readiness = curated_only`, поэтому
   автоматических четвёрок для них не собирается. Solver и валидатор структуру
   учитывают; наполнение — ручная работа.
3. **28 связей в очереди `candidate`.** Редкие слова, по которым SWOW не даёт
   ответа. В игру не идут.
4. **Мета-цепи не реализованы.** Схема и точки расширения есть, механика
   в играбельной версии — нет.
5. **Модель сложности не калибрована на телеметрии.** Это объяснимая эвристика,
   а не прогноз win rate, и так она и называется.
6. **Дедупликация принципов не применена.** `dedupe-concepts` нашёл 13 пар
   `parent_child` (сливать нельзя) и 4 пары под вопрос человеку; безопасных
   слияний в текущей базе не нашлось. Отчёт —
   `data/content/category_duplicates.csv`.
