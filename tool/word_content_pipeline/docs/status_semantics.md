# Словарь статусов: одна ось — один вопрос

Документ отвечает на два вопроса: что означает каждый статус в базе и почему
для целевой модели не заведён второй, параллельный словарь.

Главный принцип всей системы:

```text
база данных   = машинно проверенный пул кандидатов
генератор     = сборка уровня и автоматические проверки
ручная оценка = приёмка собранного уровня целиком
```

Отсюда прямое следствие: **на словах, значениях, категориях, связях и четвёрках
нет и не будет статуса `human_approved`.** Человек не подтверждает восемнадцать
тысяч связей по одной. Он смотрит готовый уровень и говорит «беру» или «не беру».
Ручное решение живёт только в `level_instances.status`.

## Почему не заведён второй словарь статусов

В задании перечислены целевые оси (`semantic_status`, `eligibility_tier`,
`validation_state`, `origin`). Три из четырёх уже существуют в базе под своими
именами и со своей семантикой. Заводить рядом новые колонки с похожими
значениями — верный способ получить базу, где одна связь одновременно
`approved` и `blocked`, и никто не знает, какая колонка главнее.

Поэтому статусы **переиспользуются**, а недостающие — добавляются как отдельная,
не пересекающаяся по смыслу ось.

| Ось из задания | Что в базе | Решение |
|---|---|---|
| `semantic_status` | `memberships.semantic_status` | Уже есть, значения совпадают один в один: `unreviewed / correct / disputed / incorrect` |
| `eligibility_tier` | `memberships.review_status` | Уже есть, но словарь шире и полезнее. Не переименовываем, даём проекцию (ниже) |
| `validation_state` | не было | Добавлено: `memberships.validation_state`, `quartets.validation_state` |
| `origin` | `memberships.source` | Уже есть. Дополнено на четвёрках: `quartets.origin` |

## Оси и их значения

### 1. `memberships.review_status` — игровая пригодность связи

Отвечает на вопрос «в каком уровне это слово можно показать в этой категории».

| Значение | Смысл | Проекция на `eligibility_tier` задания |
|---|---|---|
| `candidate` | ждёт машинной или ручной проверки, в игру не идёт | `blocked` |
| `approved` | значение, которое игрок вспоминает первым (`monitor -> COMPUTER PARTS`) | `normal` |
| `alternative` | верное и узнаваемое, но не первое (`monitor -> HOSPITAL THINGS`): материал ловушек | `normal` |
| `hard_only` | верно, но игрок сам не догадается (`monitor -> LIZARDS`) | `hard` |
| `rejected` | в игру не идёт | `blocked` |

Проекция вычисляется представлением `v_membership_eligibility`, отдельной
колонки под неё нет: два источника правды об одном факте рано или поздно
разъедутся.

### 2. `memberships.semantic_status` — семантическая корректность

Отдельная ось от пригодности: связь бывает `correct` и при этом `hard_only`.
`incorrect` закрывает связь для игры независимо от `review_status`.

### 3. `memberships.validation_state` — результат машинных валидаторов

Новая ось. Отвечает только за автоматические проверки и ни за что больше.

| Значение | Смысл |
|---|---|
| `valid` | все машинные проверки пройдены |
| `warning` | есть замечание, связь работает (например, редкое слово) |
| `invalid` | машинная проверка провалена: нет значения у многозначного слова, POS не совпал с типом связи |

Причины лежат текстом в `validation_reasons` — машинно читаемые коды через `;`.

### 4. `memberships.sense_mode` — как связь обращается со словом

`NULL sense_id` раньше значил две разные вещи: «значение не проставили» и
«значение здесь неприменимо». Теперь это разводится явно.

| Значение | Смысл | Нужен `sense_id` |
|---|---|---|
| `lexical` | связь про значение слова (`bat -> ANIMALS`) | да, если у слова больше одного значения |
| `surface_form` | связь про написание, не про смысл (`ring -> WORDS BEFORE TONE`) | нет |
| `compound` | слово участвует как часть составного (`key -> KEYSTONE`) | нет |
| `phrase_pattern` | слово в шаблоне фразы (`snow -> ___BALL`) | нет |

### 5. `memberships.source` / `quartets.origin` — происхождение

`seed / imported / derived / ai_generated`. Это **только происхождение**.
`ai_generated` не значит «хуже» и не значит «не проверено» — за проверки
отвечает `validation_state`, за качество финального уровня — приёмка уровня.

### 6. `quartets.validation_state` — состояние четвёрки

Заменяет прежний `review_state`, где было значение `human_approved`.

| Было (`review_state`) | Стало (`validation_state`) | Почему |
|---|---|---|
| `auto_validated` | `auto_validated` | без изменений |
| `human_approved` | `auto_validated` | стадии ручного подтверждения четвёрок в процессе нет; записей с этим значением в базе не было |
| `rejected` | `invalid` | «отклонена» — это результат валидатора, а не приговор человека |
| — | `proposed` | предложена генератором, валидаторы ещё не отработали |
| — | `warning` | пригодна, но с замечанием |
| — | `disabled` | выключена точечным feedback из отклонённого уровня |

`quartets.solver_state` со значением `unique` **переименован**: он проверял
только «четвёрка не лежит целиком в другой категории», а звучал как
доказательство уникальности уровня. Новое имя — `local_check`, значения
`unchecked / local_unique / local_ambiguous`. Уникальность уровня живёт
исключительно в `level_instances.solution_count`.

### 7. `categories.readiness` — готовность категории к автосборке

`unknown / ready / constrained / curated_only / hard_only / blocked`.
Выводится из пулов командой `derive-readiness`, руками не правится.

### 8. `level_instances.status` — жизненный цикл уровня

Единственное место, где появляется решение человека.

| Значение | Смысл |
|---|---|
| `candidate` | уровень собран генератором, полная проверка не пройдена |
| `solver_valid` | exact-cover solver вернул `solution_count == 1`, автопроверки пройдены |
| `review_pending` | попал в review-пакет, ждёт человека |
| `accepted` | человек принял уровень целиком |
| `rejected` | человек отклонил |
| `needs_changes` | почти годен, назван конкретный дефект |

Статус называется `status`, а не `human_approved`: `solver_valid` ставит машина,
`accepted` — человек, и это один и тот же жизненный цикл одной сущности.

## Коды причин отклонения

Причина фиксируется на уровне и, если применимо, точечно возвращается в базу
как блокировка конкретного объекта.

| Код | Куда возвращается |
|---|---|
| `bad_membership` | `memberships.review_status = 'rejected'` |
| `bad_sense` | `memberships.validation_state = 'invalid'` + очередь на разведение значений |
| `weak_category_variant` | `categories.status = 'disabled'` |
| `weak_quartet` | `quartets.validation_state = 'disabled'` |
| `level_only_conflict` | ничего в базе: дефект есть только у этой комбинации |
| `ui_text_problem` | ничего в базе: правится текст категории |
| `risk_problem` | `memberships.risk_flags` |
| `campaign_repeat` | ничего в базе: правится cooldown-конфиг |
| `wrong_difficulty` | ничего в базе: правится целевая сложность уровня |

Три кода из девяти намеренно ничего не пишут в базу: дефект принадлежит уровню,
а не контенту. Возвращать его в общий пул — значит вычёркивать нормальные слова
из-за одной неудачной комбинации.

## Что не является статусом качества

- `origin` — происхождение, не качество;
- `validation_state` — машинная проверка, не мнение человека;
- `solution_count` — свойство уровня, не свойство четвёрки;
- `accepted_level_use_count` на четвёрке — агрегат из истории уровней,
  вычисляется, а не проставляется вручную.
