# Архитектура контентной системы

## Один принцип, из которого следует всё остальное

```text
база данных   = машинно проверенный пул кандидатов
генератор     = сборка уровня и автоматические проверки
ручная оценка = приёмка собранного уровня целиком
```

Из него следуют три решения, которые определяют всю систему.

**На словах, значениях, категориях, связях и четвёрках нет ручного статуса.**
Восемнадцать тысяч связей человек по одной не подтвердит — а если сделать вид,
что подтвердил, база начнёт врать. Вместо этого хранится происхождение
(`origin`) и результат машинных валидаторов (`validation_state`). Единственное
место с решением человека — `level_instances.status`.

**Уровень собирается из конкретных четвёрок, а не из пулов.** Пул отвечает на
вопрос «какие слова вообще подходят категории». Уровню нужен другой ответ:
«какие ровно четыре слова показать». Случайный выбор четырёх слов из пула во
время игры — прямой путь к уровню с двумя правильными ответами.

**Источник правды текстовый.** SQLite — воспроизводимый снимок, а не оригинал.
Любое изменение живёт в `data/seed/*` или `data/content/*` и переживает
пересборку.

## Слои данных

```text
word                 каноническое написание, частотность
  └─ word sense      конкретное значение: definition, POS, display_text
       │
category concept     семантический принцип группировки (birds_of_prey)
  └─ category variant  игровая формулировка (BIRDS OF PREY / RAPTORS)
       └─ membership   потенциальная связь слово+значение -> вариант
            │
quartet variant      ровно четыре токена для конкретного варианта
  └─ quartet_words   slot 1..4, значение и роль каждого токена
       │
level instance       уровень как сущность: статус, сложность, хеш
  ├─ level_groups    группа = ссылка на конкретную четвёрку
  ├─ level_tokens    что видит игрок: надпись, значение, режим
  ├─ level_solver_runs  каждый запуск solver'а с версией и входом
  └─ level_decisions    решение человека и его причины
```

### Почему `categories` не переименована в `category_variants`

Категория в этой базе всегда была игровой формулировкой — то есть variant.
На её `id` ссылаются 18 775 связей, 3 197 четвёрок и слой конфликтов.
Переименование таблицы дало бы «правильные» имена ценой миграции всех ссылок
и потери стабильных идентификаторов. Вместо этого над ней надстроен
`category_concepts`, а `categories.concept_id` связывает формулировку
с принципом. Читателю схемы это объясняет комментарий в `schema.sql`.

## Проверки: три разных вопроса

Их постоянно путают, поэтому они разведены по именам и по коду.

| Вопрос | Кто отвечает | Где хранится |
|---|---|---|
| Слово вообще принадлежит категории? | `semantic_status` | membership |
| Четвёрка не лежит целиком в чужом пуле? | `solver.quartet_locally_unique` | `quartets.local_check` |
| У уровня ровно один ответ? | `level_solver.solve_level` | `level_instances.solution_count` |

Третий вопрос — единственный, который что-то говорит о пригодности уровня.
Первые два его не заменяют: две локально безупречные четвёрки в одном уровне
дают два ответа, если у них есть общее слово.

## Конвейер

```text
source content (data/seed, data/content)
  → normalize            нормализация слов, значений, ключей
  → resolve senses       карта значений: слово+категория -> значение
  → validate memberships familiarity-гейт, sense-гейт, риски
  → build quartet candidates   ограниченный разнообразный набор
  → validate quartets    состав, структура, локальная однозначность
  → assemble level candidate   непротиворечивые категории + cooldown
  → full-level solver    exact cover, solution_count == 1
  → policy / UI / cooldown     повторы, длина надписей, риски
  → export level review package
  → человек: accept / reject / needs_changes
  → точечный feedback обратно в базу
```

Каждый отказ имеет машинно читаемый код причины. Никакой шаг не считает
«не знаю» успехом: таймаут solver'а блокирует уровень так же, как найденное
второе разбиение.

## Что осталось точкой расширения

`level_dependencies` и `meta_edges` заведены, но не наполняются: текущая
играбельная версия не умеет механику «решённая категория становится словом
следующего уровня». Внедрять большую мета-подсистему до того, как её умеет
игра, значит писать код без обратной связи. Схема и место под неё есть,
реализация — в Phase 4.
