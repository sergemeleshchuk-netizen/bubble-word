# Приёмка уровня

## Где именно человек принимает решение

Единственная точка ручной оценки — собранный уровень. Не слово, не связь,
не категория, не четвёрка. Причина простая: посмотреть на восемнадцать тысяч
связей по одной невозможно, а сделать вид, что посмотрел, — значит записать
в базу ложь. Зато посмотреть на готовый уровень занимает минуту и отвечает
сразу на все вопросы, которые важны.

```text
source content
  → машинные проверки
  → четвёрки-кандидаты
  → сборка уровня
  → solver полного уровня
  → политика / UI / повторы
  → пакет на приёмку
  → человек: accept / reject / needs_changes
  → принятый уровень фиксируется, причина отказа возвращается точечно
```

## Что человек оценивает

Пакет собран так, чтобы на все эти вопросы можно было ответить, не открывая базу:

- понятны ли категории — есть формулировка и правило;
- естественны ли именно эти четыре слова — есть состав со значениями;
- нет ли натянутой связи — есть список слов, которые подходят и другим категориям;
- единственно ли решение — есть `solution_count` и отчёт solver'а;
- какая сложность — есть оценка с разбором по компонентам;
- есть ли доступный первый ход — виден по составу и оценке;
- не повторяется ли уровень с соседними — есть список повторов;
- влезает ли текст — есть предупреждения о длинных надписях;
- нет ли рисков — есть риск-статусы;
- соответствует ли прогрессии — есть целевая и фактическая сложность.

## Команды

```bash
# 1. Собрать уровни-кандидаты
word-content generate-level-candidates --db database/content.sqlite \
    --limit 10 --categories 5 --seed 20260731 --explain

# 2. Проверить их целиком
word-content validate-levels --db database/content.sqlite

# 3. Выгрузить пакет на приёмку
word-content export-level-review-pack --db database/content.sqlite \
    --output data/content/level_review

# 4. Заполнить level_decisions.csv и применить
word-content apply-level-decisions --db database/content.sqlite \
    --input data/content/level_review/level_decisions.csv
```

Шаг 3 переводит уровни в `review_pending`: иначе непонятно, что уже отдано
человеку, а что ещё нет.

## Файлы пакета

| Файл | Что внутри |
|---|---|
| `LEVELS.md` | отчёт для чтения глазами: таблица категорий, конкурирующие слова, повторы, предупреждения |
| `levels.json` | те же данные машинно: для скриптов и сравнения версий |
| `level_decisions.csv` | бланк решений; существующий файл не затирается повторной выгрузкой |

## Формат решений

| Колонка | Значение |
|---|---|
| `level_key` | какой уровень |
| `decision` | `accept` / `reject` / `needs_changes` |
| `review_note` | комментарий свободным текстом |
| `rejection_reason_codes` | коды причин через `;` |
| `target_kind` | `membership` / `quartet` / `category` / `word` / `level` |
| `target_ref` | ссылка на объект: ключ четвёрки, ключ категории или `слово>категория` |

Пример строки: отклонить уровень из-за натянутой четвёрки.

```csv
level_key,decision,review_note,rejection_reason_codes,target_kind,target_ref
L004,reject,четвёрка натянута,weak_quartet,quartet,knights_and_armor__1
```

## Точечный feedback

Уровень отклоняют целиком, но причина, если она названа, возвращается на
конкретный объект — чтобы та же ошибка не повторилась в следующем уровне.

| Код | Что происходит в базе |
|---|---|
| `bad_membership` | связь получает `review_status = rejected` |
| `bad_sense` | связь получает `validation_state = invalid` |
| `weak_category_variant` | категория получает `status = disabled` |
| `weak_quartet` | четвёрка получает `validation_state = disabled` |
| `risk_problem` | связь отклоняется с пометкой причины |
| `level_only_conflict` | ничего |
| `ui_text_problem` | ничего |
| `campaign_repeat` | ничего |
| `wrong_difficulty` | ничего |

Четыре кода намеренно ничего не меняют в базе. Дефект принадлежит комбинации,
а не контенту: если из-за одной неудачной пары категорий вычёркивать нормальные
слова, база будет беднеть с каждым отклонённым уровнем.

Каждая причина записывается в `level_decision_reasons` с пометкой, применилась
она к базе или нет. Отчёт о том, что «изменений не потребовалось», — тоже
результат, и он сохраняется.

## Что накапливается само

- `quartets.accepted_level_use_count` и `rejected_level_use_count` —
  счётчики из истории уровней, руками не проставляются;
- `quartets.last_rejection_reason` — последняя причина отключения;
- принятые уровни постепенно образуют regression-набор: их состав зафиксирован
  хешем содержимого, и пересборка кандидатов не затирает принятый уровень.

Отдельной цели «набрать 500 подтверждённых человеком четвёрок» нет и не будет.
Четвёрки внутри принятого уровня считаются проверенными **в контексте этого
уровня** — глобального ручного статуса они не получают.
