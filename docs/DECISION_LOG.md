# DECISION_LOG — журнал решений

Одна строка на развилку: что выбрано и почему. Записывается по ходу работы,
не восстанавливается в последний день.

---

## Решения, унаследованные из спеки и подтверждённые

| № | Развилка | Выбрано | Почему |
|---|---|---|---|
| 1 | Эталон: целевая игра или выгрузка 199 уровней конкурента | оба, с разными ролями | Выгрузка даёт кривую сложности (20 минут игры её не дают). Целевая игра даёт формат и правила. Разделение зафиксировано явно в `SPEC_AUDIT.md` |
| 2 | Воспроизводить кривую 1–200 или продолжать с 201 | продолжать с 201 | Воспроизведение — «повторил чужое». Оценивают продуктовое суждение |
| 3 | Единица контента: пул или граф атрибутов | граф атрибутов | Пулы воспроизводят проблему масштабирования, которую задание просит решить |
| 4 | Где стоит AI | офлайн-обогащение базы, не сборка уровня | AI в горячем пути = неуправляемая сложность и невоспроизводимый брак |
| 5 | Оценка сложности | формула + слепой решатель + ручное ревью | Формула — измерение без контроля; решатель — контроль измерения; расхождение — сигнал |
| 6 | Категория внутри: однотипная или смешанная | смешанная, с порогом по силе связи | 91% категорий референса — свободная ассоциация. Чистая таксономия даёт мёртвый контент |

## Решения этого проекта

### 7. Переиспользовать наработки предыдущего подхода

**Выбрано:** перенести из папки `BB` три актива — разбор целевой игры по
видеозаписям, контентную базу и играбельный прототип. Всё остальное строить заново
по плану.

**Почему:** разбор 4 записей геймплея по кадрам — это закрытый раздел 17.4 спеки
(лимит ходов, досыпка, хронология механик), его невозможно получить иначе, чем
играя. Контентная база на 1092 категории / 17550 связей уже превышает целевой
объём из плана (250–350 категорий / 2500–4000 связей), причём статусы связей
проставлены по человеческим ассоциациям SWOW, а не «на глаз» моделью. Строить это
заново — потратить полтора дня из четырёх, чтобы получить хуже.

**Что НЕ переносится:** генератор уровней предыдущего подхода (он был skill-based,
то есть уровень собирала модель — прямое нарушение принципа детерминированности),
скоринг, валидатор, сайт-отчёт.

### 8. Статический хостинг вместо serverless

**Выбрано:** React + Vite, всё считается в браузере на immutable snapshot базы,
деплой статикой на surge.sh.

**Почему:** главное требование к сдаче — «кликабельная ссылка без локальных
сборок», и она обязана работать у проверяющего всегда. Serverless-прокси добавляет
две точки отказа (истёк ключ, упала функция) ради одной демонстрационной
возможности. Живой AI-вызов заменён на сохранённые прогоны: в интерфейсе видно
промпт, сырой ответ модели, вердикт критика и решение человека — то есть видно
**больше**, чем показала бы кнопка «спросить модель сейчас».

**Цена решения названа честно:** свободное текстовое пожелание парсится
детерминированным разбором с готовым словарём тем, а не живым вызовом модели.
Промпт `intent_parser` в репозитории есть, его прогоны сохранены, но в браузере
работает офлайн-версия.

### 9. Мета-глубина 3 — рычаг с пометкой Unverified

**Выбрано:** оставить в генераторе, применить не более чем на одном уровне блока,
в отчёте пометить как непроверенное в целевой игре.

**Почему:** в референсе глубина 3 не встречается ни разу — это чистый
неиспользованный запас (Measured). Но мета-категории вообще не наблюдались
в первых 20 уровнях целевой игры (`TARGET_GAME_OBSERVATIONS.md`). Ставить главный
рост сложности на механику, наличие которой в целевой игре не подтверждено, —
риск. Поэтому основной рост берётся с редкости слов и ловушек, а глубина 3
показывается как один демонстрационный уровень.

### 10. Один модификатор в скоупе — цепи

**Выбрано:** цепи. Половинки — только как уже утверждённый вручную контент, без
генерации новых. Заморозка и скрытые пузыри — не делаем.

**Почему:** цепи — единственный модификатор, где тупик доказывается аналитически
(цикл в графе зависимостей), и они наблюдались в целевой игре на L20. Заморозка
и скрытые пузыри в целевой игре до L20 не встречаются вообще: формализовать их
правила было бы выдумыванием. Пять механик наполовину хуже одной целиком.

### 11. Ловушки поднимаются в приоритете

**Выбрано:** planned traps — второй по важности рычаг сложности после редкости слов.

**Почему:** спека занижала их роль, опираясь на то, что в референсе нет слов
в двух категориях одного уровня. Это верно, но ловушки в целевой игре наблюдались
напрямую (`ORANGE`, `CLUBS`, `SOIL`) и работают через другой механизм: одно слово
при наличии второй правдоподобной категории на поле. Подробно — `SPEC_AUDIT.md` §16.

### 12. Границы утверждений в интерфейсе

**Выбрано:** слово `proof` появляется только там, где есть графовый инвариант или
полный обход состояний. Случайные прогоны называются `stress test`.

**Почему:** «50 из 50 прошло» — не доказательство, и первый же вопрос проверяющего
будет именно об этом. Дешевле быть точным, чем защищать неточность.

## Зафиксированный MVP (freeze)

Правило: пока не работает вертикальный срез, ничего из P1 не начинается.

### P0 — обязательно

| Компонент | Критерий готовности |
|---|---|
| Аудит данных и спеки | воспроизводится одной командой |
| Разбор целевой игры | таблица «наблюдали / подтверждено / неизвестно» |
| Контентный snapshot | immutable JSON + sha256 |
| Генератор блока | 10 уровней из конфига или объяснимый отказ |
| Детерминированность | тот же вход → тот же `level_spec_hash` |
| Валидатор | все hard-инварианты, понятные ошибки |
| Единственность решения | 0 / 1 / 2+ глобальных раскладок |
| D | прозрачная разбивка, три части, версия весов |
| I | четыре композита, ручная рубрика |
| UI | 6 экранов, ритм блока виден глазом |
| Playable | финальные уровни реально играются |
| Экспорт | pipeline JSON + game JSON |
| Финальный пакет | 10 уровней, каждый сыгран руками |
| Отчёты | AI-воркфлоу с реальными ошибками модели |

### P1 — только после P0

Живая интерпретация свободного текста через прокси, живое расширение базы,
несколько независимых прогонов решателя на уровень, ручное редактирование уровня
с автоматическим пересчётом.

### P2 — сознательно вне скоупа

Заморозка и скрытые пузыри, база на 100 000 связей, аналитика игроков,
персональная сложность, локализация, физический bubble-движок, CP-SAT,
обучение модели интересности, живой AI как обязательная часть генерации.
