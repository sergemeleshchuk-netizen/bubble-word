# Bubble Level Forge: AI-инструмент генерации уровней

Тестовое задание: веб-инструмент для игры Bubble Associations: Word Game
(пазл «разложи пузыри со словами по категориям»). Инструмент генерирует уровни
с помощью AI, проверяет их решаемость, оценивает сложность и экспортирует JSON.

Этот файл подгружается автоматически. Подробные правила: `rules.md`,
инструкции для AI-агентов: `AGENTS.md`, текущее состояние: `status.md`.

## Структура проекта

- `site/` - сайт-отчёт о выполнении задания (деплой на serge-mel.surge.sh)
- `tool/` - сам веб-инструмент (появится по ходу работы)
- `levels/` - сгенерированные уровни в JSON (сдаём 10 штук с оценками)
- `reference/` - видео и скриншоты целевой игры (в git не попадает)

## Ключевые договорённости

- История изменений ведётся через git: каждый смысловой шаг = коммит с понятным сообщением.
- Секретный ключ AI-провайдера не хранится ни в статических файлах, ни в репозитории:
  страница ходит к AI через серверный прокси, ключ живёт только в настройках хостинга прокси.
- Деплой сайта — ТОЛЬКО из коммита: `cd tool/level-tool && npm run deploy:commit -- <ref>`
  (по умолчанию HEAD; `DRY=1` показывает, что уедет, ничего не публикуя).
  Скрипт выкладывает временный git worktree указанного коммита, поэтому чужие
  незакоммиченные правки и временные файлы на продакшен не уезжают.
  Прямой `npx surge ./site serge-mel.surge.sh` (он же `npm run deploy:site`)
  публикует папку с диска КАК ЕСТЬ — годится только когда над проектом работает
  одна сессия. Повод правила (03.08): деплой правок инструмента унёс на сайт
  незаконченный фикс прототипа из другой сессии и её временный файл
  `site/playable/_refcheck.json`.
- Ветка НЕ изолирует файлы: рабочий каталог один, `git checkout -b` копии не
  делает, и параллельная сессия правит те же файлы и коммитит в ту же ветку
  (03.08: фикс половинок лёг в ветку `tool-ux-cleanup`, к которой не относится).
  Работаете параллельно — своя копия на сессию: `git worktree add ../BB-<тема> -b <ветка>`.
  Перед деплоем ветки влить `main`, иначе публикация откатит сайт на состояние
  ветки — скрипт предупреждает о таких коммитах, но не мешает.
- Инструмент генерации уровней живёт на том же сайте: `serge-mel.surge.sh/tool/`
  (решение 31.07: отдельный домен `bubble-level-tool.surge.sh` больше не целевой)
  и встроен iframe'ом в блок 05 «Level Design Tool» — он идёт ДО «Build Playable».
  Бандл подгружается при первом раскрытии пункта (`data-src` + `toggle()`),
  иначе каждый читатель отчёта молча тянул бы несколько мегабайт.
  Деплой инструмента вместе с сайтом: `cd tool/level-tool && npm run deploy:site`.
  Собранный инструмент лежит в `site/tool/` и коммитится — сайт обязан
  деплоиться из репозитория без предварительной сборки.
- Версия инструмента живёт в `tool/level-tool/web/src/core/version.ts`, журнал —
  `tool/level-tool/CHANGELOG.md`. Поднять версию без строки в журнале не даст тест.
- Генератор словесный/семантический: модификаторы (цепи) выключены и в интерфейсе,
  и в генерации. Включать обратно — только вместе с полным набором механик, иначе
  одна механика перекашивает оценку D. Поле `allowedModifiers` и механика цепи
  в типах и в прототипе сохранены.
- Собранный пакет уезжает в играбельный прототип кнопкой «Добавить в Playable»
  через `localStorage` (общий origin). Ключ и формат — один источник правды:
  `tool/level-tool/web/src/core/playableHandoff.ts`; его читают `site/index.html`
  и `site/playable/index.html`, и это закреплено тестом `playable_handoff`.
- «Готово/verified» говорим только после проверки в реальном браузере.
